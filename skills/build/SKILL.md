# 개발 실행 (Phase 4)

설계한 팀으로 계획의 태스크를 하나씩 돈다.
당신은 오케스트레이터다. 직접 짜지 않고 **조율한다.**

## 흐름

```
지시서 작성 → 구현자 디스패치 → 보고 확인 → 다음 태스크
                                              │
                              (태스크 2~3개마다) 리뷰어 디스패치
                                              ↓
                          합격 ←─ 아니오 ─ 수정 디스패치 (상한 2회)
```

**리뷰는 태스크마다가 아니라 묶음마다다.** 한 태스크는 리뷰어가 판정하기에
너무 작아서, 매번 붙이면 컨텍스트를 다시 쌓는 비용이 리뷰 값어치를 넘는다.
다만 묶음을 3개 넘게 키우지 않는다 — 반려됐을 때 되돌릴 양이 커진다.

## 팀 모드로 돌릴 때

→ [`references/team-mode.md`](references/team-mode.md) — 팀 모드(에이전트끼리 직접 왕복)로 돌릴 때의 도구와 규칙

## 1. 지시서를 파일로 넘긴다

디스패치 프롬프트에 붙여 넣은 것은 **세션이 끝날 때까지 내 컨텍스트에 남는다.**
매 턴 다시 읽힌다. 그래서 큰 것은 파일로 주고 경로만 넘긴다.

`_workspace/briefs/task-N.md` 에 계획의 해당 태스크 전문을 옮긴다.

디스패치 프롬프트에는 다섯 가지만 담는다.

1. 이 태스크가 프로젝트에서 어디에 해당하는지 (한 줄)
2. 지시서 경로 — "이걸 먼저 읽어라. 이게 요구사항이고 값은 그대로 쓴다"
3. 앞 태스크가 만든 인터페이스 (지시서가 알 수 없는 것)
4. 지시서에서 내가 발견한 모호함의 해소
5. 보고서를 쓸 경로

**세션 히스토리를 붙여 넣지 않는다.** "태스크 1~3 이후 상태" 같은 요약을
뒤 태스크 지시서에 넣지 않는다. 새 에이전트에게 필요한 것은 자기 태스크와
맞닿은 인터페이스뿐이다.

## 2. 구현자 디스패치

`.claude/agents/`의 구현자를 `subagent_type`으로 지정한다.
모델은 넘기지 않는다 — 세션 모델이 상속되고, effort는 정의 파일이 정한다.

구현자는 이걸 한다: 지시서를 읽고 → TDD 사이클을 돌고 → 커밋하고 → 보고한다.

**"결과를 스스로 다시 검토해라"를 지시서에 쓰지 않는다.** 시키지 않아도
하고, 시키면 자기 확인이 겹쳐 토큰만 더 쓴다. 검토는 리뷰어의 일이다.

**한 번에 한 명만 디스패치한다.** 여러 구현자를 병렬로 띄우면 같은 파일을
건드려 충돌한다.

## 3. 보고 상태별 처리

| 상태 | 처리 |
|---|---|
| **DONE** | 리뷰로 넘어간다 |
| **DONE_WITH_CONCERNS** | 우려를 먼저 읽는다. 정확성·범위 문제면 리뷰 전에 해결한다. 관찰("이 파일이 커지고 있다")이면 기록하고 진행 |
| **NEEDS_CONTEXT** | 빠진 정보를 주고 다시 디스패치한다 |
| **BLOCKED** | 원인을 판단한다. 컨텍스트 문제면 보강, 태스크가 너무 크면 쪼갬, 계획이 틀렸으면 **사람에게 올린다** |

**BLOCKED를 무시하고 같은 조건으로 재시도하지 않는다.** 막혔다고 했으면
무언가 바뀌어야 한다.

## 4. 리뷰어 디스패치

태스크 2~3개가 끝날 때마다 한 번 부른다. 태스크마다 부르지 않는다.

리뷰어에게 주는 것: 지시서 경로 · 변경된 코드 · 이 태스크에 걸리는 절대 규칙.

**구현자의 보고서를 주지 않는다.** 구현자의 설명을 읽으면 그 설명에 끌려간다.
지시서와 코드만 보고 판정해야 한다.

리뷰어는 두 가지를 판정한다.

| 판정 | 묻는 것 |
|---|---|
| **명세 준수** | 요구한 것을 다 했나. 요구하지 않은 것을 했나 |
| **코드 품질** | SOLID·주석·테스트 품질·과잉설계 |

둘 다 나와야 리뷰가 끝난 것이다. 하나만 오면 다시 받는다.

**리뷰어에게 미리 판단을 주지 않는다.** "이건 지적하지 마라", "이건 계획이
정한 것이다" 같은 문장을 프롬프트에 쓰지 않는다. 리뷰 라운드를 아끼려고
결론을 미리 박는 것이고, 그러면 리뷰가 형식이 된다.

## 4.5 되돌리기 비싼 판정은 셋에게 묻는다

리뷰어 하나의 판정이 곧 결론이면, 그 하나가 틀렸을 때 막을 것이 없다.
**판정이 뒤집혔을 때 되돌리는 값이 큰 것**만 셋에게 묻는다.

| 셋에게 묻는다 | 하나로 충분하다 |
|---|---|
| 치명·중대로 올릴 지적 | 사소·관찰 |
| 머지를 막을 지적 | 다음 카드로 미룰 것 |
| 계획을 바꿀 지적 | 계획 안에서 고칠 것 |

**투표자 셋은 서로를 모른다.** 같은 발견을 렌즈만 달리해 각각 디스패치하고,
**다른 투표자가 뭐라 했는지 알려 주지 않는다.** 렌즈는 어디에 노력을 쏟을지를
정할 뿐 판정 기준을 바꾸지 않는다 — 기준은 셋 다 같다.

렌즈는 이 기능에서 판정이 갈릴 축으로 고른다. 자주 쓰는 셋:

| 렌즈 | 묻는 것 |
|---|---|
| **도달성** | 이 경로가 실제로 닿나. 기본 설정에서도 그런가 |
| **영향** | 닿으면 정말 문제인가. 주장한 결과가 진짜 결과인가 |
| **방어** | 이미 막고 있는 것이 있나. 한 프레임 위의 검사·프레임워크 기본값 |

각 투표자는 표 하나를 파일로 남긴다.

```json
{"finding_id": "F1", "lens": "도달성",
 "verdict": "TRUE_POSITIVE", "evidence": "src/A.java:42 — 여기서 검사 없이 넘어간다"}
```

**표는 내가 세지 않는다.**

```bash
"${CLAUDE_PLUGIN_ROOT}/skills/build/scripts/panel-tally.py" _workspace/panel/F1
```

`KEEP` 만 수정 루프로 보낸다. `DROP` 은 사유와 함께 기록하고 넘어간다 —
**표가 모자라서 `DROP` 이 된 것은 「아니다」가 아니라 「모른다」이므로,
다시 물을지는 내가 정하되 그 사실을 기록에 남긴다.**

## 5. 수정 루프

치명·중대 지적은 **한 번에 하나씩 고치지 않고 모아서 한 명에게** 넘긴다.
지적마다 수정자를 띄우면 매번 컨텍스트를 다시 쌓고 테스트를 다시 돌린다.

경미한 지적은 기록해두고 최종 검사에서 함께 판단한다.

**상한 2회.** 3회째도 반려면 사람에게 올린다. 무엇이 왜 반복 실패하는지
요약해서.

**계획이 시킨 것을 리뷰어가 결함이라고 하면** 그건 사람이 정할 문제다.
지적과 계획 원문을 나란히 보여주고 어느 쪽이 맞는지 묻는다. 계획이 시켰다는
이유로 지적을 묵살하지 않고, 계획에 어긋나는 수정을 묻지 않고 시키지도 않는다.

## 6. 진행 기록

컨텍스트가 압축되면 대화 기억은 사라진다. 실제 세션에서 이미 끝난 태스크를
통째로 다시 실행한 사례가 있다 — 가장 비싼 실패다.

태스크 하나가 끝날 때마다 `_workspace/progress.md`에 한 줄 남긴다.

```
태스크 3: 완료 (리뷰 통과)
  - feat: ping을 수신과 분리된 전용 스케줄러에서 보낸다
  - feat: 실패 콜백이 던져도 ping 스케줄러가 멈추지 않는다
```

**해시가 아니라 커밋 제목으로 가리킨다.** Phase 5에서 왕복 이력을 접으면
(규칙 2) 해시가 통째로 바뀌어 **여기 적은 것이 전부 죽은 참조가 된다.**
제목은 접혀도 남는다 — 접기의 기준이 하위 기능이고, 제목이 그 단위다.

**태스크 하나가 커밋 여럿을 낳으면 전부 적는다.** 하나만 적으면 압축 뒤에
어디까지 끝났는지 알 수 없다. 제목이 겹치면 뒤에 짧은 구분을 붙인다.

압축 후에는 **내 기억보다 이 파일과 `git log`를 믿는다.**

## 7. 중간에 사용자에게 묻지 않는다

계획을 실행하라고 받았으면 실행한다. "계속할까요?" 같은 확인은 시간을 뺏는다.

멈추는 경우는 셋뿐이다: 해결할 수 없는 BLOCKED, 진행이 불가능한 모호함,
모든 태스크 완료.

## 8. 커밋

각 커밋은 절대 규칙 2번을 만족한다 — 테스트가 통과한 상태, 한 문장으로
설명되는 크기.

**이건 훅이 안 막는다.** 커밋 직전에 테스트를 돌리고 초록을 눈으로 확인한다.
0.5.0에서 시각 비교로 추측하던 검사를 뺐다 — 오탐이 많아 우회를 부르고,
`inspect`가 커밋을 하나씩 체크아웃해 실제로 돌려보는 편이 정확하다.

`Co-Authored-By`를 넣지 않는다 (규칙 8).

## 다음
