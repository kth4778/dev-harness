# 회고 (Phase 7)

이번 세션에서 저지른 실수를 다음 세션이 반복하지 않게 만든다.
**같은 실수가 세 번째로 나오지 않게 하는 것**이 목적이다.

이 스킬이 하네스가 쓸수록 똑똑해지는 유일한 경로다. 이걸 건너뛰면
하네스는 처음 만든 그대로 멈춰 있고, 같은 실수를 매 세션 반복한다.

## 재료

| 무엇 | 어디서 |
|---|---|
| 이번 세션의 지적 | `_workspace/`의 리뷰·검사 파일 |
| 이번 세션의 막힘 | `_workspace/`의 보고서에 적힌 BLOCKED·우려 |
| 봇 지적 | PR의 리뷰 코멘트 |
| **과거 세션 기록** | `_archive/*/workspace/09_session_log.md` |
| 사용자가 나를 우회한 순간 | 이번 대화. 사용자가 직접 손댄 곳 |

마지막 항목이 가장 중요하다. **사용자가 하네스를 우회해 직접 작업했다면
그 지점이 하네스의 구멍이다.**

## 승격 사다리

```
1회 발생   → 기록만 한다 ("관찰 중")
2회 이상   → 규칙화를 제안한다
```

반복 판정은 감이 아니라 대조로 한다. 과거 `_archive/`의 세션 기록에 같은
유형이 있으면 반복이다. 없으면 1회다.

**1회를 바로 규칙화하지 않는다.** 규칙이 늘어나면 규칙을 안 읽게 된다.

**실수가 없었던 세션도 회고한다.** 그때는 "잘 된 것"을 기록한다 — 어떤 판단이
통했는지가 다음 하네스 설계의 재료다. 쓸 게 없다고 건너뛰면 성공 사례가
하나도 안 쌓인다.

## 어디에 반영하나

| 문제의 성격 | 반영처 |
|---|---|
| 결과물 품질이 낮았다 | 해당 **스킬** |
| 필요한 역할이 없었다 | **에이전트 정의** (다음 하네스 설계에 반영) |
| 순서가 틀렸다 | **오케스트레이터** 또는 `bootstrap`의 Phase 표 |
| 특정 모듈에서만 반복된다 | 그 모듈의 **3층 CLAUDE.md** |
| 프로젝트 전반의 습관이다 | **2층 CLAUDE.md** |
| **기계로 판정 가능하다** | **훅** — 가장 강한 강제 |

**마지막 줄을 먼저 본다.** 규칙을 글로 써도 안 지켜지는 것이 반복되면,
그건 규칙을 더 강하게 쓸 문제가 아니라 **훅으로 옮길 문제**다.

판정 기준: "이 위반을 코드가 판정할 수 있나?" 판정할 수 있으면 훅이다.
글로 쓰는 것은 사람의 판단이 필요한 것만 남긴다.

## 사람 승인 게이트 — 필수

**규칙 변경은 반드시 사용자 승인을 받는다.** 내가 스스로 하네스 규칙을
고치면 귀찮은 규칙을 느슨하게 바꾸는 방향으로 변질된다.

제안 형식:

```
회고 결과 — "커밋에 목적이 둘 섞임" 지적이 2회 반복됐습니다
(2026-07-29 로그인, 2026-08-05 클립승인).

제안: commit-guard 훅에 검사 추가
+ 커밋 메시지에 "그리고"·"및"·","로 이어진 목적이 둘 이상이면 차단

반영할까요? (예 / 아니오 / 수정)
```

- 승인 → 반영하고 세션 기록에 승격 내역을 남긴다.
  **`RULES.md` 에 절을 더하는 것으로 끝나지 않는다** — 승격 규칙이 흐르는
  자리는 전부 동적(제목 grep)이라 따로 갱신할 것이 없지만, **새 절의 제목이
  `## `(번호 없음)으로 시작하는지** 확인한다. `###` 로 넣으면 주입·게이트가
  전부 못 본다 (codex, PR #77~#79 세 라운드가 이 전파 문제였다)
- 거부 → **거부 사유도 기록한다.** 다음 회고에서 같은 제안을 반복하지 않기 위해서다
