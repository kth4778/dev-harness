## 규모가 크면 먼저 쪼갠다

요청이 독립적인 하위 시스템 여러 개를 담고 있으면, 세부 질문을 시작하기 전에
그 사실을 먼저 말한다. **세션 하나는 기능 하나다.** 각 하위 시스템이 자기
PRD·계획·PR을 갖는다.

## 위험 신호 — 이 생각이 들면 멈춘다

| 생각 | 현실 |
|---|---|
| "간단해서 설계까지는 필요 없다" | 간단해 보이는 요청일수록 가정이 숨는다. |
| "일단 만들고 피드백받자" | 만든 뒤의 피드백은 되돌리는 비용이 붙는다. |
| "이 정도는 상식적으로 이렇게 하지" | 상식은 사람마다 다르다. 묻는 데 30초, 되돌리는 데 하루. |
| "질문이 너무 많아 짜증날 것 같다" | 잘못 만든 걸 다시 만드는 게 더 짜증난다. 점수를 보여주면 끝이 보인다. |
| "한꺼번에 물어보면 빠르겠다" | 묶으면 뒤쪽 답이 부실해진다. 하나씩. |
| "코드 좀 보고 나서 물어보자" | 조사는 맞다. 다만 조사 결과를 근거로 **질문**해야 한다. |
