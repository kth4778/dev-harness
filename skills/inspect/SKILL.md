# 전수 검사 (Phase 5)

PR을 올리기 전에 **절대 규칙 10개 + 알려진 결함 점검**을 검사한다.
하나라도 FAIL이면 PR을 올리지 않는다.

**11번이 가장 자주 놓치는 항목이다.** 규칙 1~10은 기계로 확인되는데,
"알면서 미룬 것"은 내 머릿속에만 있어서 조용히 넘어간다.
실제로 그렇게 올린 PR에 커밋이 둘 더 붙고 봇 재리뷰가 두 바퀴 더 돌았다.

**6번은 여기서만 값이 싸다.** `README.md`는 커밋되는 파일이라 이 PR에 못 태우면
**문서 PR을 하나 더 올려야 한다.** `CLAUDE.md`만 최신인 상태는 최신이 아니다 —
그 파일은 커밋되지 않아 팀원에게 도달하지 않는다.

**봇은 확인 도장을 받는 자리지 수리공이 아니다.** 여기서 잡을 것을 봇에게
떠넘기면 리뷰 라운드가 배로 늘고, 그 왕복이 개발보다 오래 걸린다.

## 검사 대상

```bash
BASE=$(git merge-base HEAD "origin/$(git symbolic-ref -q --short refs/remotes/origin/HEAD | sed 's|^origin/||')")
git diff --stat "$BASE"..HEAD
git log --oneline "$BASE"..HEAD
```

## 시작 전 — 도장이 유효한가

**검토자의 통과 도장은 시각이 아니라 커밋 해시에 붙는다.**

```bash
git diff --name-only "$(cat .harness/stamp)"..HEAD -- '*/src/main/*' 'src/main/*'
```

**결과가 비어 있지 않으면 검사를 시작하지 않는다.** 검토자가 본 것은 그 해시의
코드이고, 그 뒤의 변경은 아무도 안 봤다. 바뀐 부분을 검토자에게 다시 보내고
통과한 뒤 도장을 갱신한다.

2026-08-06에 이걸 안 보고 전수 검사를 통과시켰다. `verifier` 도장 뒤에 운영 파일
7개가 소켓 계층까지 바꿨는데 아무도 안 봤고, PR 직전에 사람이 막았다. 다시 검토를
붙이니 **치명 2 · 중대 1**이 나왔다.

`stamp-guard` 훅이 `gh pr create`에서 같은 것을 막지만, **막힌 뒤에 아는 것보다
시작 전에 아는 것이 싸다.** 전부 PASS한 뒤 도장을 현재 HEAD로 갱신한다.

```bash
git rev-parse HEAD > .harness/stamp
```

## 10개 판정

→ [`references/checklist.md`](references/checklist.md) — 10개 판정 항목의 판정 기준 전문

**승격된 규칙도 게이트다.** 이름을 여기 적지 않는다 — 적으면 다음 승격 때
이 목록이 낡는다(codex, PR #79). **`RULES.md` 의 번호 없는 `##` 절 전부**가
대상이다. 그 자리에서 뽑는다:

```bash
# 설치본에서는 작업 폴더가 대상 프로젝트다 — 상대 경로면 없는 파일이 된다.
grep -E '^## ' "${CLAUDE_PLUGIN_ROOT}/RULES.md" | grep -vE '^## [0-9]+\.'
```

절마다 「이번 변경이 이 절에 해당하는 작업이었나」를 묻고, 해당하면 지켰는지
확인해 판정표에 적는다. 해당 없으면 「해당 없음」이라 적는다 — 빈칸과
「확인했고 없음」은 다르다.

## 추가: 실제로 돌려본다

**이것이 이 스킬의 존재 이유다.** 테스트가 전부 통과해도 서버가 안 뜨는 일이 있다 —
**실제로 그랬다. 빌드 산출물이 깨져 있었고 테스트는 전부 초록이었다.**

`verifier` 에이전트를 디스패치하거나 직접 한다.

```bash
docker compose up -d          # 인프라
./gradlew :{모듈}:bootRun     # 서버 (모노레포는 빌드 루트에서 — 예: services/)
```

1. **"Started" 로그를 눈으로 확인**한다
2. 이번 기능의 엔드포인트를 **성공·실패 케이스 각각** 호출한다
3. 응답을 **요약하지 않고 그대로** 기록한다

인프라가 꺼져 있으면 켠다. "인프라가 필요합니다"로 넘기지 않는다.

## FAIL이면

고치고 **처음부터 다시 검사한다.** 고친 항목만 다시 보지 않는다 —
수정이 다른 항목을 깨뜨릴 수 있다.

2회 고쳐도 같은 항목이 FAIL이면 사람에게 올린다.
